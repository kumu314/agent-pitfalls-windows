# 编辑与脚本操作精确性坑（根因 + 对策）

> 跨项目通用。每条结构：**现象 / 根因（忽视了什么·哪个行动出错）/ 对策**。
> 来源：2026-09 数模论文收口轮踩坑。

## 1. heredoc 吞反斜杠（脚本注入失败）
- **现象**：Bash heredoc 里写 Python 代码含 `\\theta`（正则匹配 LaTeX 反斜杠），落地变 `\t heta`，正则匹配全空。
- **根因**：heredoc 会消化一层反斜杠转义；**行动出错**——在 heredoc 里直接写多层转义的正则。
- **对策**：① 能用 Edit/Write 工具写文件就不用 heredoc；② 必须 heredoc 时用 `chr(92)` 构造反斜杠，或按行号定位而非正则；③ 写完先 `python -c` 打印一小段验证再跑全量。

## 2. old_string 不唯一 / 不精确（编辑失败与误伤）
- **现象**：Edit 报错"not unique"，或替换了错误位置的相同文本。
- **根因**：用太短的片段做锚点；忽视同片段在文中多处出现。
- **对策**：锚点带上前后各 1-2 行上下文保证唯一；批量改用 `replace_all` 前先 Grep 数出现次数（应与预期一致）。

## 3. 正则"识别器"误伤正文（样式脚本 bug）
- **现象**：docx 样式脚本用 `startswith('表')` + 含数字判断"表题"，把正文句"表 3-1 同时是第四章求解流程……"误判为表题并居中/加粗。
- **根因**：识别器只看**开头特征**，没排除"以图表号开头的正文句"；遗漏"题注的构成特征"（短 + 无句读）。
- **对策**：题注判据收紧为 **组合条件**：长度 ≤40 字符 **且** 不含句号/分号/逗号/冒号 **且** 开头匹配 `^(图|表)\d+-\d+`；再把识别结果列成清单人工抽查一遍。

## 4. 全角/ASCII 符号差异破坏下游解析（数据契约 bug）
- **现象**：上游契约文件里写了全角减号 `−2.5`，`fill.py` 的正则 `-?\d+` 只认 ASCII `-`，渲染成 `+2.5`，符号直接反了。
- **根因**：忽视"上游文件是机器解析的，符号必须按解析器口径写"；肉眼看着对 ≠ 机器读对。
- **对策**：给机器读的数值字段只用 ASCII `- + . e`；含 Unicode 数学符号的文件入库前跑一遍 `grep -P '[−×≤≥]'` 抽查；解析器正则对负号的处理要有单测。

## 5. Markdown 标题层级不一致（结构混乱）
- **现象**：各章文件有的用 `#` 当章、有的用 `##` 当章，组装后层级跳变。
- **根因**：多人/多轮产出没有约定层级规范，组装前未校验。
- **对策**：约定一次并写进规范（章=`#`、节=`##`、小节=`###`）；组装脚本里加层级连续性断言（不允许跳级）。

## 6. 满盘/大目录解析极慢（超时假死）
- **现象**：C 盘 100% 满时 `du`/全盘 find 长时间无输出，拖死会话。
- **根因**：磁盘满导致元数据操作变慢 + 全量递归本身 O(文件数)；**行动出错**——明知满盘还跑全量递归。
- **对策**：① 降维：`du -d1` 逐层、或直接对可疑目录定点扫；② 长命令一律 `run_in_background`，主线程先做别的；③ 给命令设合理预期，超 2 分钟无输出就换定向策略，不硬等。

## 7. 同一文件并行 Edit → 后写覆盖先写（静默丢改动）
- **现象**：一条消息里对**同一个文件**发多个 Edit，每个都返回 `Successfully edited`，但最后只有一部分生效，另一些改动凭空消失。实测表现：`NameError: name 'SELF_SKIP' is not defined`（新增的定义被同批的循环改动覆盖）；以及某行已改成 `600–800` 后被"还原"回旧值。
- **根因**：并行 Edit 各自基于**同一份旧快照**做替换，后写者整文件回写，覆盖掉先写者的结果；工具**不报错**，属静默丢改动。
- **对策**：① 一批 Edit 只要落**同一个文件**，必须**逐条串行**（一条消息一个 Edit）；**不同文件**才可并行。② 改完用 Grep / `python -c` 计数**复核关键改动是否都在**，别只信 "Successfully edited"。③ 出现"干净样本退出码 1"这类怪现象时，先 `py_compile` + 打印**真实 stderr** —— 本次根因是 NameError 把退出码带成 1，不是逻辑错。

## 8. `python -c "..."` 内联脚本里的**反引号**被 shell 命令替换吃掉（2026-09-12 实测，同一类错误一天犯两次）
- **现象**：用 `python -c "长字符串"` 往文件里追加 Markdown，执行成功、字符数也对，但**内容里所有 `\`xxx\`` 反引号片段全变成空**（``claim_audit.md` 指出` → ` 指出`）。stderr 里能看到 `bash: consistency.json: command not found` —— 这是**命令替换**在执行那段文本。
- **同族**：`cat <<EOF` heredoc（不带引号定界符）里的反引号、`$(...)`、`${...}` 同样被展开；**中文引号 `“”` 也可能被吃**。
- **根因**：Bash 对双引号串内的 `` ` `` 与 `$()` 做**命令替换**，与"是不是 python 参数"无关。
- **对策（按优先级）**：
  1. **首选：不要用 shell 传长文本** —— 用 Write 工具直接写文件；改文件用 Edit（字面匹配，无 shell 参与）。
  2. 必须 heredoc 时，定界符**加引号**：`<<'EOF'`（单引号内含反引号安全）。
  3. 必须 `python -c` 时，把脚本写成**文件**再 `python file.py`，不要在命令行内联长文本。
  4. 写完**必查**：`grep -c '`' file` 或搜关键词，确认反引号内容还在；只看"追加了 N 字符"会漏。
- **教训**：这条坑其实早有记录（"heredoc 内含反引号会被 shell 吃"），但记录写的是 heredoc —— 于是换到 `python -c` 时又踩一次。**同类坑要按"shell 传文本"这一族来记，不要按具体命令记。**

## 9. 日志类文件"追加"变"覆盖"（静默丢历史）
- **现象**：给日志 / 看板 / CHANGELOG 追加一段，结果把上一段整段替掉，只能事后凭记忆补回。
- **根因**：对只增不改的文件用了整段 Edit；工具不区分"追加"和"替换"，取决于你给的 `new_string` 里留没留旧内容。
- **对策（append-only 铁律）**：
  1. 先 `Read` 文件尾部若干行；
  2. 把尾部内容**原样保留**在 `new_string` 开头；
  3. 新内容追加在其后。
- **已付过的学费**：两次这么干过，两次都丢了上一段日志。

## 10. Windows PowerShell 的编码与 BOM（中文乱码）
- **现象**：`.ps1` 脚本里的中文在执行时乱码，或 Edit/Write 改过之后脚本"不生效"。
- **根因**：PowerShell 5.1 读**无 BOM** 的 UTF-8 中文会按系统代码页解释；改文件时 BOM 被抹掉。
- **对策**：
  - PowerShell 脚本一律存 **UTF-8 with BOM**；改完复查 `head -c 3 <file>` 应为 `ef bb bf`。
  - 读写文件显式指定 UTF-8，不依赖系统默认编码。
  - 终端本身乱码是控制台代码页问题 → `chcp 65001`。

## 11. Git Bash 里的盘符路径写法
- **现象**：Git Bash 中 `cd /d/xxx` 偶发解析异常（路径看起来对，命令说找不到）。
- **根因**：MSYS 路径转换与含中文/空格目录混用时不稳。
- **对策**：改用 `cd "D:/xxx"`（正斜杠 + 盘符 + 引号）；含中文或空格的路径一律加引号。
