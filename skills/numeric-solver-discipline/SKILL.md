# 数值求解纪律（血泪版）

> 来源：2026-09 一次数值优化任务的 coder 复盘（一条比步进宽度还窄的约束被整段跳过，结果偏小 40%+ 且表面完全正常）。

## 1. 自适应步进点 ≠ 约束采样（最贵的一课）
- **现象**：约束窗口很窄，求解器自适应步进点整段跳过 → 约束从未触发 → 结果偏小且无任何报错。
- **根因**：把积分器输出点当成约束判定采样点。
- **对策**：`solve_ivp(..., dense_output=True)`，然后在**独立细网格**（≥4000 点，按最窄约束窗口的宽度反推所需步长）上重采样判约束；真正的离散事件（触发、碰撞、状态切换）用 `events` 机制，不靠采样碰运气。

## 2. 交付前三方对账（缺一不提交）
1. 我的实现
2. **独立方法**（不同积分器 / 手写 RK4 / 解析解）
3. **参考值**（预演量级 / 文献 / 量纲检验）
- 方差 <5% 才算验证通过；对不上时**先穷尽自检，才有资格质疑参考值**。

## 3. 边界用二分显式求，不要靠扫描端点猜
- 可行域下界常被**另一条你想不到的约束**卡住（你以为卡在 A，实际卡在 B）。
- 做法：先探端点与物理极限，再对可行/不可行的切换区间做二分，显式给出边界值 + 是哪条约束在卡。

## 4. 「可复现」不是自称的
- 声明 reproducible 前：干净工作区重跑一遍，`diff` 除时间戳外应零差异；同时记录 seed、求解器版本、rtol/atol。

## 5. 数值进论文一律占位符 + 脚本回填
- 禁止手抄数字（手抄值与程序输出漂移是硬伤高发区）；换口径时图注/正文/代码/数据四处同步改，再跑一次对账脚本全绿才算收口。

## 复用信号
出现"结果看起来合理但偏小""约束从没被触发过""扫描曲线太平滑""换个积分器结果就变"→ 先怀疑采样与对账，而不是怀疑物理模型。
