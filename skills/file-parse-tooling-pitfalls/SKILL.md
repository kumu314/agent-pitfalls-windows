# 文件解析与工具操作常见坑（根因 + 对策）

> 跨项目通用。每条结构：**现象 / 根因（忽视了什么·遗漏了什么·哪个行动出错）/ 对策**。
> 来源：2026-09 数模论文评估与资产库维护中多次踩坑复盘。

## 1. docx 公式抽取变空白（读取解析缺失）
- **现象**：zipfile 解 `word/document.xml` 后只抽 `<w:t>`，公式处成空白，误判"公式丢失/乱码"。
- **根因**：忽视了 Word 数学公式在独立命名空间 `<m:oMath>` 内，文本节点是 `<m:t>` 而非 `<w:t>`；只抽正文节点 = 丢公式。
- **对策**：按 `</w:p>` 切段，每段内联同时抽 `<w:t>` 与 `<m:t>`（正则 `<(?:w|m):t[^>]*>(.*?)</(?:w|m):t>`）；表格同理（`<w:tc>` 内段落）。一次抽取即还原正文+公式。

## 2. PDF 手解流乱码（读取解析失败）
- **现象**：用标准库 zlib 手解 PDF 流，回退逻辑把压缩字节当文本 → 乱码 / matched=0。
- **根因**：遗漏 PDF 流多种滤镜/编码；**行动出错**——手搓二进制格式解析器。
- **对策**：装 `pdfminer.six`，`from pdfminer.high_level import extract_text` 一次提取；核对公式渲染用 extract_text 后统计 `$` 字面残留（应=0）、θ/°/×/≤ 符号数。绝不顺手手解二进制。

## 3. 抽取脚本递进三次（本可简化却复杂）
- **现象**：为抽同一篇 docx 连写 extract_docx → extract_docx2 → extract_tbl 三个脚本。
- **根因**：未一次性设计抽取（正文+公式+表格+关键词定位），边跑边补。
- **对策**：第一版就写"单趟抽取"：切段 → 段内 w:t+m:t → 按关键词/表标记定位 → 输出目标区域。避免脚本增殖。

## 4. 改已有文件前未 Read（编辑失败）
- **现象**：Edit 报 `File has not been read yet`。
- **根因**：违反工具前置条件；**行动出错**——未读即改。
- **对策**：任何对已有文件的 Edit / 覆盖式 Write，先 Read（或确认本轮已读过）。未知内容的覆盖写必读。

## 5. 假设工具存在（编辑/收尾失败）
- **现象**：收尾时调用某个"把文件呈现给用户"的宿主端工具（各家 agent 客户端工具名不同，别家可能根本没有这个工具），报"工具不存在"，打断交付。
- **根因**：忽视了"指令文档列出的工具 ≠ 当前真实工具集"。
- **对策**：依赖某工具前先确认其在可用集；不可用时优雅降级（如文本中给文件路径代替预览）。不在关键路径假设未验证工具。

## 6. 资产库编号撞车（工作引发的组织 bug）
- **现象**：增量维护的文件夹出现两个 `05_`、两个 `06_`。
- **根因**：每轮本地"取下一个空号"，遗漏统一编号权威/清单；**行动出错**——无 manifest 就 ad hoc 编号。
- **对策**：维护多文件集合时建单一索引/清单（README 或 MEMORY 段），编号只从清单分配；新增先查重。

## 7. 复制前未确认源布局（工作引发的路径 bug）
- **现象**：批量 cp 报"文件不在根目录"（实际在 `子目录/代码/`）。
- **根因**：假设扁平结构；遗漏复制前先 `ls` 实际布局。
- **对策**：批量操作前先列源树确认层级，再写通配/路径。

## 8. Glob 空结果误判（读取解析误判）
- **现象**：Glob 对含中文长路径返回 `No files found`，误以为目录空。
- **根因**：Glob 通配/编码对中文路径不稳；**行动出错**——单一否定结果即下结论。
- **对策**：Glob 空时 fallback 到 Bash `ls` 复核，不采信单一空结果。

## 9. 沙箱出网需代理 / 完全无外网（网络失败）
- **现象**：curl 直连市场/API 失败；或 `git push --dry-run` 报 `Recv failure: Connection was reset`。
- **根因**：忽视了本机系统代理，以及"沙箱可能根本连不上外网"这一层；遗漏出网前先实测连通性。
- **对策**：
  - 本机有 Windows 系统代理时，curl 加 `-x http://127.0.0.1:<端口>`（端口以 `HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyServer` 为准）；git 亦需 `http.proxy`。
  - **确认是无外网就别重试**：直接切换为"本地提交 + 由用户在真实终端推送"，重试只是烧轮次。
  - GitHub API 匿名访问限流（403/429）时不要轮询重试，改读本地已 clone 的文件。
  - **每次开工都实测一次连通性**，不要拿上一次的结论推断这一次。

## 复用信号
出现"解析出来是空/乱码""Edit 报错""目录像空""编号重复""出网不通"→ 先对照本 skill 而非继续硬试。

## 边界
本 skill 只管"**怎么把文件读准**"。读完之后的内容一致性与数字对账属于任务层，不在这里。
